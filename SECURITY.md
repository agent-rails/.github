# Security policy

## Supported versions

Unless a repository states otherwise, security fixes target the latest release and the current default branch. Early-stage or unreleased projects may support only the current default branch.

## Reporting a vulnerability

Do not disclose suspected vulnerabilities in a public issue, discussion, pull request, commit, or chat transcript.

Use the affected repository's **Security** tab and select **Report a vulnerability**. Include:

- the affected project, version, or commit;
- the threat scenario and expected security boundary;
- reproduction steps or a minimal proof of concept;
- likely impact and any known mitigations;
- whether the issue is already public.

If private vulnerability reporting is unavailable, open a minimal public issue requesting a private contact channel without including technical details.

Reports will be assessed before public disclosure. Please allow maintainers reasonable time to reproduce, remediate, and coordinate a release.

Repository-specific security policies and threat models take precedence over this default.
