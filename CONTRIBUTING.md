# Contributing

Agent Rails projects are early systems work for reliable and governed AI agents. Contributions are welcome when they improve evidence, safety, interoperability, or operational usefulness.

High-value contributions include:

- reproduced failure cases and minimal reproductions;
- adversarial tests and fail-closed behavior checks;
- real-world authorization policies and integrations;
- benchmark or evaluation improvements;
- documentation of unexpected behavior and operational limits.

## Before changing code

Open or join an issue for substantial changes so scope and design can be discussed first. Small fixes may go directly to a pull request.

Read the target repository's README and any local `CONTRIBUTING.md`. Repository-specific guidance overrides this default.

## Pull requests

1. Branch from the current default branch.
2. Keep the change focused on one concern.
3. Add tests for changed behavior, including relevant failure paths.
4. Run the repository's documented checks.
5. Use a conventional commit prefix such as `feat`, `fix`, `docs`, `test`, `refactor`, `ci`, or `chore`.
6. Open the pull request as a draft while it is still changing.
7. Explain what changed, why, how it was verified, and what is deliberately out of scope.

Never include credentials, customer data, private infrastructure details, or undisclosed vulnerability information in issues, commits, test fixtures, or logs.

By contributing, you agree that your contribution is licensed under the target repository's license.
